# 零碎知识剪藏：现行完整流程

核对日期：2026-10-16。本文整理当前程序已经具备的功能，包含同页分叉 Tab 和共享卡片区；模型策略、卡片内容格式、导入目标和恢复规则沿用现有设置。

2026-10-07/08 的原生问答开发交接是历史输入。其“辅助结果先采纳”“问答不建日期目录”等旧设计已被后续确认的实现更新；现在分别采用辅助结果校验后直接生效，以及类型目录内按确认日期追加。当前运行包以 [README](../README.md) 为准，详细操作以 [问答与组合制卡](chat-workflow.md) 为准。

## 1. 采集材料与选择入口

- 主输入框支持文字、一张或多张图片、纯图、图文混合。Enter 进入同一问答页面，提交成功后清空输入；不依赖末尾问号分流。
- 文字浮点为“读 / 卡 / 摘 / 问”；图片浮点另有“图”。选区与图片沿原有捕获、上下文及素材保存流程处理。
- 普通“卡”和主输入打开问答页后等待发送。普通“卡”使用已配置的 Codex 类型默认策略；主输入仍允许选择服务、模型和推理。
- 最右“问”使用既有 API 快捷问配置和快速问答类型，页面就绪后发送一次；不自动导出。加载失败或重复就绪不会自动换模型或重发。
- 原快捷制卡、原图/OCR、语言学习及摘录选项继续按原设置运行；快捷失败仍回到原草稿继续处理。

## 2. 多轮问答

1. 选择服务、真实模型/推理和问题类型。普通“卡”默认 Codex `gpt-6.1-sol`：快速答案为 `low`，其他类型为 `high`；这些是当前本机配置，不是新增策略。
2. 每次发送前读取当前类型、共同规则、已绑定背景和明确启用的示例，保存规则原文/哈希与本轮设置快照。
3. 输入文字或图片并发送。Codex 使用官方 ChatGPT 登录的独立 SDK/App Server；API 使用原凭据配置。每个 Tab 保留自己的服务、模型、输入和原生身份；右上“新建对话”和 Tab 末尾“＋”均在当前页面新建空白 Tab。
4. 流式显示回答，原始 Markdown、LaTeX、图片与 Mermaid 源码随草稿保存。页面先显示最近 20 条，较早消息仍可分页访问。
5. 停止、关闭或重开继续沿原状态机：保存输入、部分回复和回合身份；不能确认完成时保留未知状态。

打开历史、选消息、编辑、排序、复制和预览均不调用模型。只有发送和明确的辅助动作会调用模型。

## 3. 从对话组成卡片

1. 将可见消息加入正面、背面或两面；所有对话 Tab 共用右侧的多张卡片，可以跨分支选材。加入的是原始材料，公式和图片引用保持可回读。消息右侧“分叉”保留截至该位置的上下文，在同页新 Tab 继续；从提问分叉会回填该问题，等待手动发送。
2. 正反面可以手工编辑、补文字、在光标处粘图，以及维护各自的批注。手工编辑后追加消息保留已有内容；移除/重排来源不会悄悄覆盖手工正文。
3. 按需要执行现有辅助动作：整合对话、书面化问题/答案、当前面图转文字、全部书面化、单面批注书面化。整合在卡面空白时默认使用全部保留对话；有选材或手工稿时以其为重点，参考对话补足内容，支持跨 Tab 和智能多卡，也可在补充要求中指定张数。API 辅助停止或失败后可主动重试，原不确定记录保留。
4. 辅助动作使用独立的服务、模型、推理和补充要求，不跟随主对话切换。已有 Mermaid/清洗开关仍只随这些明确动作发送。
5. 结果完整校验后直接更新规定字段，保留其他字段和原始材料；失败、缺字段或迟到结果不能覆盖新稿。辅助处理及手工编辑沿同一撤销/重做记录保存。

四个内容区始终分开：正面、背面、正面批注、背面批注。全部书面化一次核验并更新四区，一次撤销恢复；单面动作只处理对应范围。

## 4. 预览、确认与冻结

1. “预览卡片”使用当前编辑稿显示 Markdown、大纲、公式、图片和 Mermaid，不产生模型请求。
2. 确认导入时，经统一 `CardImportRouter` 冻结内容、目标、类型/目录、日期、媒体哈希和导出身份，保存独立导出子草稿。
3. 写入及核验使用原冻结计划。确认后的设置变化不改变该次目标；再次修改卡稿时沿既有规则产生新的导出稿，原身份继续保留。
4. `Verified` 表示远端回读已经通过。重复操作同一已核验导出不再次添加卡片；“写入返回成功”本身不等于验收完成。

## 5. 导入 RemNote

1. 检查专用 host/plugin 的连接、写入许可和本次内容要求的能力。
2. 新问答和组合卡精确核对类型 document，路径为“零碎知识剪藏 → 零碎知识制卡 → 提问类型 → 确认当日 M.d”。同日复用日期目录，正文按生成顺序追加，批次尾空行规则不变。
3. 通过专用本机 HTTP → WebSocket → RemNote 官方插件 SDK 写入。插件 ID 为 `knowledge-clipper`，端口 43111/43112/43113；产品导出不经过 MCP。
4. 保存原文 RichText、正反面层级、公式、图片及 Mermaid 源码/widget 绑定；正面批注留在同一正面节点，背面批注保留独立母节点及其层级。
5. 回读核对真实节点身份、内容、父子顺序、卡片类型/数量、媒体及绑定，全部通过后标记 `Verified`。
6. 按原导航流程后台打开对应页面并选中正文；导航失败单独报告，不把已经核验的导入改为失败或再次写入。已导入历史不自动重定位。

普通模式和摘录继续使用原模式目录与日期规则。旧冻结路径、旧卡片及 journal 不迁移。

## 6. 导入 Anki

1. 按稳定身份查重，核对模型字段、托管模板和目标牌组；已有自定义模板不覆盖。
2. 保存需要的图片/离线组件，核验媒体字节，再按冻结计划写入。
3. 回读笔记字段、卡片、牌组/模板与暂停状态，并核对所有媒体哈希，通过后标记 `Verified`。
4. 正反面、批注、公式和离线 Mermaid 维持原显示；背面继续显示完整正面及分割线。

语言学习默认 Anki，其他模式默认 RemNote；个人模式目标及已冻结的旧目标优先。Anki 暂不可用时，原待导入队列继续保存并按既有规则恢复，不丢材料。

## 7. 历史记录与继续制卡

1. 打开历史列表，读取草稿、摘录及各子卡状态；问答按会话归组，导出子卡不拆成重复的顶层记录。
2. 同一会话显示卡片总数、已导入数及待核对状态，仍按原分页、搜索和操作显示。
3. “查看”或“继续制卡”进入同一问答/多卡页面；旧单轮、旧问答和误入子卡的入口解析回原会话，保留原消息、未发送输入、手工稿与冻结身份。
4. 已打开会话优先复用 live 草稿；关闭后重开读取保存状态。展示缓存不能作为新的写入或导入状态来源。
5. 历史重开自动核对磁盘，显式刷新仍可用；语言历史播放原录音，摘录回到原摘录会话。打开历史不会自动生成、补发或导入。

## 8. 其他既有分支

- “读”：继续原词典、语言判定、语音与录音复用流程，历史播放不替换原素材或制卡身份。
- 语言卡：阅读/写作模式各自保留内容、编辑、状态和导入目标；原文上下文及目标位置受校验，缺上下文沿原有选择/例句流程处理。成功模式不会因另一个模式失败而重做。
- 摘录与挖空：使用独立 session/card store；手工摘录和挖空不调用 AI，仍经过同一冻结、导入和回读机制。
- 图片：先保存真实字节/哈希，再按入口走原图或 OCR 流程；OCR/下游任务保留关联，历史打开复用原任务。取消、失败和重试不建立替代素材或重复导入。

## 9. 中断与恢复

- 模型状态 `Unknown`：Codex 仅精确核对原 Thread/Turn；API 没有等价回读时保留未知，不自动重发或换服务。
- 导入状态 `Unknown`：先用原冻结身份回读，不能重新添加或伪装成新来源；需要媒体/空行恢复时沿既有专用恢复路径完成原节点。
- 已完成导入：重复点击不重复写入。已冻结内容与当前编辑稿分开保存，修改不会取消已有远端卡片。
- 页面渲染异常：使用原“重新加载界面”恢复保存稿，不重发模型请求。

## 10. 本次性能优化及证据

只调整读取、排版和等待方式：每轮历史读取共享一次只读快照；列表批量排版；重开先显示已有投影并在后台更新；卡片导入状态显示按文件变化失效；同一进程保留一个空白 WebView2 控制器；Mermaid 在需要绘图时加载离线模块；RemNote 合并同次健康检查、并行读取独立 SDK 属性；Anki 并行读取独立信息并以最多 4 个请求核验媒体。

保留空白 WebView2 会在首次打开问答后占用一份浏览器基础进程，直到程序退出；不保留会话页面、消息或模型请求。磁盘保存格式、导入写入顺序、全部回读校验和异常恢复规则不变。
