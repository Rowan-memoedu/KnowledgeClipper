# 多轮问答与组合制卡

全链路概览见[现行完整流程](workflow-overview.md)，包括入口、双端导入、其他模式及异常恢复。本文保留具体操作和工程合同。

本功能在现有问答、草稿、历史及确认导出链路内运行。主输入框按 Enter 后统一进入同一问答页面，不再按问号或默认路径分流；支持粘贴一张或多张图片、纯图片及图文混合输入，图片计数旁的 × 移除最后一张图片。提交成功才清空输入，Esc 清空本次文字及图片。

问答历史的“查看”和“继续制卡”均进入当前 `LanguageChatForm`，不以是否存在 Chat 字段区分新旧界面。旧追问面板及桌面发送、导入事件已移除；旧记录只作兼容读取，保留原消息、手工答案、未发送输入、原图及已冻结卡片身份和目标。打开及重开不调用模型或自动导入，重复点击复用 live 会话。已关联卡片缺失或冲突时显示核对错误，不自动建立替代卡。

同一场对话的多张组合卡共用一条历史，显示总数和已导入数。导出子草稿以 `ParentDraftId` 和所属会话 `Compositions` 的双向绑定识别，继续独立保存冻结计划和远端身份；旧子卡入口解析回原会话。历史读取只作内存投影，不批量改写文件。误入旧子卡页面后新增的卡稿、批注和素材会按原卡 ID 恢复进同一多卡页面，正常编辑或关闭时随会话保存；已存在的冻结身份不替换。确实发送过新问题的分支、待恢复的独立请求、孤立草稿及损坏父链保留可访问入口。

文字浮点为“读 / 卡 / 摘 / 问”，图片浮点为“图 / 读 / 卡 / 摘 / 问”。“卡”是原“问”的改名，保留原普通问答、快捷制卡及导入行为。最右“问”打开相同问答页面，以 API、“图片解答与快捷问模型”设置（当前为 `deepseek-flash`）和 `fast-answer` 快速问答类型自动发送一次；无需再点“发送”，不自动导出，也不覆盖手动问答偏好。模型目录或发送失败时保留输入，不静默换模型；重新加载界面不会自动重发。主输入和普通“卡”仍等待手动发送。旧预览的“多轮问答与组合制卡”可继续原草稿。

## 使用

左侧对话使用同页 Tab。每条普通消息原有四个按钮右侧增加“分叉”：从回答分叉会保留此前上下文并在新 Tab 继续；从自己的提问分叉会把该问题及图片放回新 Tab 输入框，修改后手动发送。Tab 末尾“＋”和右上角“新建对话”均新建空白 Tab。原对话、分叉和新对话保持在同一个问答窗口。

所有 Tab 共用右侧卡片区，可以将不同分支消息加入同一张卡。来源列表标明所属对话，卡片编辑、批注、撤销、辅助处理及冻结导出继续原规则。各 Tab 分别保存输入、附件、服务、模型、类型及原生身份；关闭重开恢复 Tab 顺序和当前选择。生成中可以切换 Tab，回复或失败仍归属发起它的对话；页面同一时刻保留一个模型请求，不为切换、新建或分叉自动生成回复。

Codex 使用官方 `thread/fork(lastTurnId)` 截断历史并回读新身份，按完整原生回合分叉；同轮多项输出从末项分叉，已停止且身份明确的部分回答也可保留。API 使用选定位置之前的消息作为该分支后续请求的历史。未知分叉不得重建：已取得新 Thread ID 时只做精确回读，丢失新 ID 时保留原记录并报错。

1. 普通“卡”默认使用 Codex 和 `gpt-6.1-sol`，选择问题类型即可自动匹配推理：快速答案为 `low`，其他类型为 `high`。当前模型不支持 `instant`，已按用户确认使用 `low`。模型与推理框显示自动结果，无需手动选择；重开、新建和逐轮切换保留此策略。主输入页仍可自由选择；显式切换 API 后使用 API 实际目录。Codex 使用官方 ChatGPT 登录，不需要 API Key；API 仍使用原凭据设置。开始对话后若要改服务，新建空白 Tab，已有对话和共享卡片保留。
2. 输入文字或直接粘贴图片；提问框支持纯图及图文混合输入。类型和 MD 在每次发送前读取。停止会保存部分回复；Codex 同时请求原生中断。关闭在途窗口会保存输入、部分内容和原回合身份。
3. 将可见消息加入正面、背面或两面。手工编辑后再次“加入”会把原始内容追加到对应卡面，保留已有文字和另一面；切换卡片类型不再误标为手工编辑。手工稿移除或调整来源顺序时保留正文，并显示来源列表与正文的区别；可继续编辑正文，或用“全部书面化”统一整理当前卡片。正反面文本框可在光标处直接粘贴图片，可撤销最近 20 次编辑。
4. “整合所选对话”“生成书面化问题”和正反面的“图转文字”共用整合按钮下方的一组独立服务、模型及推理设置，默认 API 和当前图片解答模型（`deepseek-flash`），推理默认由该服务目录给出（当前 `high`）。这些动作不跟随主对话切换；手动选择保存于 `chat-auxiliary-preferences.json`，当前草稿中各服务保留独立身份。API 推理选项来自真实目录，并通过 `reasoning_effort` 传入请求。
5. “生成书面化问题”位于正面“补充图片”左侧：正面已有内容时整理原问题；正面为空时依据背面、所选材料及相关上下文生成问题。背面的题目＋答案截图会作为真实图片附给视觉模型，单图提取原题，多图按阅读顺序保留续页条件、小问及公式，排除答案与解析。看不清的条件标为待核对，不猜补。生成后直接替换正面，背面与批注由代码保留。
6. 正反面“补充图片”左移，原右侧位置为“图转文字”：识别对应卡面的全部图片，将题目、答案、公式及图中必要关系转成 Markdown，与前后正文衔接。背面图转文字同时处理正文与批注图片，各自保留原分区；只有批注有图也可转换，无图字段逐字保留。识别完成直接替换。整合、生成书面化问题和图转文字统一直接生效，不在底部显示候选或模型原回复，不需要再点采纳。原图与回合证据仍保存在原草稿，可撤销恢复；所有模型结果都不能覆盖更新后的卡稿，失败不重发或冒用旧回复。
7. 背面“补充图片”左侧的“添加批注”展开正文下方的独立输入框，支持 Markdown、公式和光标处直接粘贴图片，与正文共用素材登记及哈希核验。RemNote 将“批注”设为背面顶格母节点，内容及其原有层级位于其下；Anki 在正文后添加分割线，左侧显示“批注：”及内容。空批注不导出标题或分割线。卡片区域的 Ctrl+Z 与“撤销上次编辑”共用记录，补图、批注、正文编辑、书面化和图转文字都可回退；一次撤销图转文字同时恢复正文和批注原图，重开保留撤销记录。

整合生成多张卡时，一次撤销会恢复原卡并撤回本次新增卡。若新增卡已有后续编辑或已确认导出，不会将其悄悄删除；先撤回新增卡的后续编辑后可继续撤销整合。已冻结导出仍保持原有规则，撤销不重发或取消既有导入。

正反面各有四个按钮，按“生成书面化问题/答案、添加批注、补充图片、图转文字”顺序铺满操作行，小宽度自动为两列。正面“添加批注”展开正面正文下的输入框，与背面批注使用相同的图片粘贴、识别、预览、撤销与持久化路径，分别存于 `FrontAnnotation` 与兼容旧草稿的 `Annotation`。图转文字只转换当前面正文和该面批注中的图片，不改另一面的正文或批注。

“生成书面化答案”与问题书面化共用独立辅助设置。任一面已有文字、单图或多图即可使用：背面有内容时整理既有解答，背面为空时根据正面及相关上下文生成答案；只有背面存在也可整理。生成问题同样支持只有答案的输入。两种操作直接替换对应正文，原稿可撤销，另一面及双面批注保持原样。

Anki 正反面批注均采用正文后分割线与左对齐“批注：”。RemNote 的问题本身是一个 RichText Rem，其子节点属于答案，因此正面批注保留在同一个正面节点内，含换行、公式与图片；背面继续保留“批注”顶格母节点及内部层级。不会为正面批注额外生成答案或卡片。

卡片下方的原“从所选消息重新生成”改为“全部书面化”：一次请求整理正面、背面、正面批注和背面批注，正面或背面缺失时复用各自书面化动作的补齐规则。四字段完整校验后一次替换，一次撤销恢复全部原稿与图片；不凭空增加原本为空的批注。任一结果缺少原有批注、卡稿已更新或回合未完成时整次不改稿。

双面批注框展开后，右下角都有“书面化”，仅整理该批注，支持文字、图片与混排；其他三个字段由代码锁定。空批注按钮禁用。“预览卡片”独立靠操作行最右，预览仍不调用模型。
8. 预览后确认导入 RemNote 或 Anki。此时冻结内容、目标、媒体哈希和身份；再次修改建立新导出草稿并保留批注，已 Verified 的导出不会重发。选取、排序、编辑、预览、导出均不调用模型。

等待模型首个可见回复时显示“正在准备回答…”，临时回答没有制卡动作。模型目录加载完成后才能发送。若界面发生渲染异常，会显示保留草稿的恢复提示，可按“重新加载界面”继续查看，不重新发送问题；本机诊断保存在数据根的 `logs/chat-ui.jsonl`，只记录异常、草稿 ID 与阶段，不附原问题或凭据。

## 规则与本机数据

“补充要求”仍可自由输入，文本框底行提供“生成 Mermaid 图”和“去除无关信息”两个独立开关。默认关闭，选中显示蓝色，再次点击取消，可同时开启；它们与当前手写要求一起，仅在执行整合、书面化或图转文字时发送。Mermaid 是对原任务的补充，保留完整正文；清洗去除水印、题号、页码、排版标记和乱码，保留有效题干、条件、公式与解答。切换选项本身不调用模型。

Anki 出示背面时仍显示完整正面（含图片与上下文），随后以分割线显示答案；背面内已有批注分割线继续保留。应用专用的普通正反面模板同步适用于已导入卡片，正文、身份和复习进度不重建。已有自定义模板不会被自动覆盖。

默认模板在仓库 `modes/chat`；用户覆盖位于 `D:\AppData\KnowledgeClipper\modes\chat`。应用升级不会覆盖用户 MD。没有实际输入的个人背景保持空白，不推断身份或能力。

```text
question-types.json          # 稳定类型 ID、显示名、MD 引用、RemNote document ID
system.md                    # 共同规则
profiles/common.md           # 用户明确填写的共同背景
types/<type-id>.md            # 当前类型规则
few-shots/<type-id>.md        # 明确启用的参考示例
actions/integrate.md          # 整合所选对话
actions/formalize.md          # 生成书面化问题
actions/formalize-answer.md   # 生成书面化答案
actions/formalize-all.md      # 全部书面化，复用问题/答案规则
actions/formalize-annotation.md # 当前面批注书面化
actions/transcribe.md         # 指定卡面的图转文字
```

界面提供当前类型、共同背景、注册表编辑和本次规则快照入口。规则按共同规则、明确绑定的背景、当前类型、本次辅助动作合并。示例及既有对话始终为用户材料；含图示例必须有真实、哈希正确的附件。缺文件、空规则、路径越界、非法类型或不兼容模型会保留输入并报错。

每次发送保存 MD 原文/哈希、真实模型及推理选项、用户输入、图片和回合身份。原始消息、组合卡编辑稿、候选与冻结导出分开保存，均沿用 `language-drafts` 主库。`chat-media` 仅保存登记素材；不另建聊天主库或后台调度服务。个人历史、few-shot 审阅稿、凭据和运行数据不提交 Git。

辅助回合随原草稿保存于 `Chat.Auxiliary`，各服务使用独立会话和原生 Thread，不改写主对话消息、模型、推理或绑定。生成书面化问题的空正面分支会显式提供相关主对话材料；辅助会话仍会保留自己先前的上下文。停止和在途关闭保存辅助回合自己的身份与部分回复；Codex 可以“核对原辅助回合”，API 未知结果不重发。

`tools/Install-ChatReview.ps1` 可将已审阅的本地注册表和示例装入个人覆盖目录；它拒绝覆盖已有文件，不用于日常升级。当前个人审阅稿已经安装，无需重跑。通用默认模板不包含私人历史或个人 RemNote ID。

## 连接与恢复边界

当前正式入口由 `Program` 调用 `MainForm.EnableLanguageWorkflow`，经 `DesktopUi.Language` 和 `LanguageDesktopFlow` 使用既有 DraftStore、ContentModule 与 CardImportRouter。本次启动自检的 `candidateIntegrationConfigured` 为 false；`core-v3` 中的 QuestionSessionSdkBridge 属于另行配置的 NamedPipe 候选通路，未将其误当作当前正式入口，也未修改其合同或启用额外 Kernel。新增 Codex 路由在现有正式工作流内调用官方 SDK。

Codex 采用官方 `openai-codex==0.159.0` 和验收过的 `codex-cli 0.160.1`，由 `tools/Install-CodexChatRuntime.ps1` 安装到 `D:\Applications\RemNoteQuickClipperRuntime` 的独立 SDK/runtime。优先发现该目录，明确环境变量可指定已验收 runtime；不绑定桌面应用的哈希目录，不复制认证文件。升级版本后需重测实验性注入路径。

原生调用是 `thread/start` → 本地落盘 Thread ID → `thread/inject_items` → `turn/start` → 本地落盘 Turn ID → 消费可见项。子进程在收到 .NET 持久化确认后才继续有副作用的下一步。SDK 子进程不继承宿主工具管道；关闭项目文档、记忆、Shell、搜索和多代理的子进程配置不修改用户全局配置。仍不宣称彻底隔离全部原生 Skills 或继承网页 ChatGPT 记忆。

Unknown 只能精确回读原 Thread/Turn，不自动重发、新建替代会话或换 API。创建或发送回执丢失、缺少精确身份时保留未知状态，避免重复计费和重复制卡。API 没有等价的服务端回合回读接口，未知结果保留在原草稿。写入者冲突同样保留原绑定。

自动压缩的完成事件会记录在当前快照。**规则重注入合并到原生回合结束之后**，且下次发送重新读取和注入 MD；在运行中注入会使 0.160.1 继续回答，低阈值下可形成循环。已经在压缩后的上下文中生成的回答不会被软件自动重答，不能保证它完整保留了压缩前的格式规则。当前版本无手动压缩按钮。此边界有真实低阈值 Canary 和重复/丢失回执回归。

原生行为依据 [App Server 文档](https://learn.chatgpt.com/docs/app-server)；具体版本与本机验收结果一起判断，不以新版文档代替固定版本实测。

## 渲染与导出

本地 WebView2 使用 `@assistant-ui/react`、Streamdown、KaTeX 和 Mermaid，消息先呈现最近 20 条，历史全部可分页访问。资源随构建提供，严格 CSP 和受限消息桥禁止外部脚本、用户 HTML 执行及任意本地文件读取。模型返回的图片附件登记真实字节与哈希，不能用链接或路径冒充图片。

`mermaid` 代码围栏在聊天与卡片预览中渲染为 SVG，原始 Markdown 保持不变。问答及组合正反面卡导出时保留独立 Mermaid 源码部分：RemNote 保存原生代码 RichText，并由同 ID 的 KnowledgeClipper 插件 widget 显示；Anki 将原文保存在可展开的“Mermaid 源码”区，使用随包提供的本地脚本生成图形。三处使用同版 Mermaid 11.16.1，不请求 CDN，也不把图示栅格化。图形使用浅色画布以兼容夜间卡面；语法错误保留原文并显示提示。

Anki 仅在精确核验应用托管正反面模板后安装组件，保留原朗读扩展、字段和复习记录；RemNote 新写入要求 renderer capability，回读同时检查源码与 powerup 绑定。冷启动后的子节点顺序使用官方 `getChildrenRem()` 读取，不依赖可能缺省的 `children` 快照。完整验收与复现材料见 [Mermaid 验收记录](D:/Artifacts/KnowledgeClipper/mermaid-chain-20261015/validation.md)。

问答与卡片预览共用版本一致的 KaTeX 标准 HTML/MathML 和数学字体。行内公式保留文字基线；独立公式按正文左边界对齐，长公式在自身区域内横向滚动，避免随容器居中左右移动。显示归一化不覆盖原始 Markdown 与 LaTeX，复制和导出继续使用原文。

Markdig AST 识别美元及括号 LaTeX，隔离代码、转义与货币。只归一化显示副本，不改原消息；RemNote 使用原生 inline/display RichPart 与真实答案子层级，Anki 使用转义后的 HTML/数学标记。多行正面仍是一张卡，答案子项和普通箭头不产生额外卡片。

左侧消息提供“复制整条”，复制与“加入卡面”相同的原始 Markdown、LaTeX 和登记图片引用。也可以选中文字加公式后按 Ctrl+C：文字按选区提取，公式按原始消息解析位置取回，保留原来的 `\(...\)`、`\[...\]`、`$...$` 或 `$$...$$`，不复制 KaTeX 的显示字形。选择公式局部时复制完整公式。选区提供纯文本与 Markdown 格式；公式无法与原文核对时明确提示改用整条复制。

左侧图片拖入正面或背面时，显示用的 `https://clipper-media.local/<哈希>.png` 链接会核对已登记素材和实际图片字节，转换为 `![图片](asset:<哈希>)`，与直接粘贴图片使用相同的预览和双端导入路径。未冻结旧草稿中的裸链接、Markdown 图片及普通图片链接也在导入解析时兼容；不联网下载，不改变外部 URL 或代码中的字面链接，不重发已有冻结导出。

新问答和组合卡使用注册表精确绑定的“零碎知识剪藏 → 零碎知识制卡 → 类型 document → 当日日期 document”，确认前验证类型 ID、标题、document 属性、祖先和 trash 排除。日期由确认当日本地时间按 M.d 生成，同日复用；正文及空行完全复用普通摘录的按序追加和批次尾空行规则，不加批次目录或学习正文元数据。旧冻结身份不迁移；退役“问答”目标禁止新写入，未知旧导出仍允许按原身份核对。

RemNote 沿用独立 `knowledge-clipper` host/plugin、原插件 ID、协议及 journal（HTTP 43111、WS 43112、安装服务 43113），增加可选 `knowledge-clipper.question-composition.v1`。旧插件未加载此能力时拒绝新组合结构，不降级丢失层级。产品不依赖 RemNote MCP。

## 发布与回滚

当前正式包、运行路径和验收回执以 README 的“当前交付状态”为准，历史过程统一收在 `docs/release-history.md`。任务 XML、快捷方式及 host 配置保留在对应部署产物的 `rollback`。文档中的历史授权不作为其他任务的重启许可；当前正在使用的应用按当前会话的用户授权处理。

切换沿用既有桌面快捷方式、`Personal Tool - KnowledgeClipper` 和 `KnowledgeClipper RemNote SDK` 任务，只更换执行/部署路径；不建立第二个服务或端口。新版插件加载并报告能力后，先用独立公开 document 验证真实导出/媒体回读，再启用正式入口。测试超时包装会在结束时关闭其 Windows Job 内的子进程；长期运行的应用应由既有计划任务启动，或在包装外使用原生进程启动，再单独有界检查存活与健康状态。

回滚恢复记录下来的原任务、快捷方式和 host/plugin 路径后重启相关应用，保留新草稿、导出身份、媒体和 journal。不要删除已导出卡片、把 Unknown 改成 Ready 或用旧版软件重新导入新组合草稿。旧版本不提供新聊天界面，但本地新增字段应保留给重新启用新版时继续处理。
