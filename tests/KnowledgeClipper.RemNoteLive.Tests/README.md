This CLI uses handwritten public fixtures and the production `CardImportRouter`, `ExcerptCards`, `QuestionCards`, and `LanguageModeCards`. It never calls an LLM or synthesizes speech; its result does not validate prompt quality.

Arguments:

```text
KnowledgeClipper.RemNoteLive.Tests <project-root> <fixed-data-root> <receipt.json> <image-fixture-directory> --prepare|--live [--sdk-endpoint URL] [--anki-endpoint URL]
```

Use the same data and receipt paths for every retry. This matrix accepts only `D:\Caches\KnowledgeClipper\standalone-remnote-live`, and rejects the old v1 manifest/report rather than extending or overwriting earlier fixtures. Receipts stay beneath `D:\Artifacts\KnowledgeClipper`. The image directory is the output of `tools/New-ImageRoutingFixtures.ps1`, containing `question-1.png`, `question-2.png`, `answer-1.png`, and `answer-2.png`. Existing verified local copies are reused.

The independent SDK host defaults to `http://127.0.0.1:43111`. Saved fixtures using the former standard HTTP loopback endpoint on port 43101 resolve to this host without rewriting their settings, source IDs, or frozen plans. Custom endpoints remain unchanged. A missing journal for an uncertain import remains a readback failure and never permits a replacement export.

`--prepare` creates the stable fixture manifest, local drafts, and frozen export plans through production batch confirmation paths with a no-network importer. `FixtureMatrix.cs` independently declares literal card faces, native cloze groups/hints, formula types, image order, paths, and counts; these expectations are not generated by the production converter. The resulting `expected-matrix.json` records all final items, including the history item created later during live execution. Preparation leaves imports unverified. Its receipt outcome is `PREPARED_NO_EXTERNAL_CALLS`, with `passed: false` because no live success is claimed.

`--live` prepares any missing local fixture state, then performs the actual imports. Each successful production import is followed by an independent readback. RemNote readback uses `RemNoteConnection.Validate` with the previous receipt and separately compares raw SDK nodes against the handwritten matrix. Anki readback uses `VerifyAsync` plus a unique ClipId-tag lookup. Reopened batches must issue no `export`, `finalize-media`, or `addNote` request and retain the same IDs, followed by another forced readback. Request traces record local URL, port, operation, and source ID; acceptance requires every SDK request to use 43111 and no request to use 43101 or 43102.
