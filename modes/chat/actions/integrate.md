# 整合对话制卡

本轮任务是整合学习材料并生成完整卡片，按本动作的 JSON 合同输出；不要只回答某一条原问题。只依据当前输入快照提供的材料；以前的辅助请求和输出是处理记录，不自动成为本次材料。不要根据内容被放在正面还是背面、选取了几条消息或当前有几张卡来决定生成数量。

- `contextScope` 为 `all-conversations`：正反面及选材为空，以 `context` 中全部保留对话为材料。`conversations` 标明各 Tab 的消息范围；共享前缀只使用一次，各分支的不同条件、替代方法和结论分别核对，不把互斥分支混成事实。
- `contextScope` 为 `selected-and-draft`：以 `messages` 中跨 Tab 选取的材料、正反面手工稿及批注为重点，参考 `context` 中的原题和追问补齐必要条件、证明、动机和符号。卡面摆放只是输入收集方式，可重新组织；不要把未选取且不相关的话题另行制卡，也不要丢弃手工补充。
- 按独立学习目标智能决定一张或多张卡：同一问题的追问应归入其完整问题和答案；相互独立、可单独学习的目标适合分卡。每张卡的问题须独立可理解，答案完整，避免机械地一条消息一张卡。未指定数量时不默认只做一张。
- `requestedCardCount` 不为空时，必须恰好生成该数量，按知识目标合并或拆分，不能用重复卡、空卡或虚构内容凑数。未指定时生成 1 至 20 张。优先使用输入卡片的 `typeId`；只有内容明显属于另一允许类型时才使用其他 `allowedTypes`。
- 执行 `requirements` 中的补充要求。只使用实际提供的材料，部分或未知回复只按已有内容处理，不补造缺失原题。

仅返回 JSON 对象：{"cards":[{"front":"独立可理解的问题 Markdown","back":"完整答案 Markdown","typeId":"输入允许的类型 ID"}]}。数组顺序就是卡片顺序。公式保留原 LaTeX，Mermaid 保留代码围栏；图片只能引用输入中已登记的 ![说明](asset:SHA256)，不可虚构链接。来源仅留在本地映射，不在卡面追加审计元数据。
